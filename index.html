5 → 2checkout steps

Shortening a multi-vendor checkout

Context
An e-commerce platform with 1,000+ vendors and a 5-step checkout.
What I saw
Studied how users actually moved through it to find the steps that added effort without helping anyone place an order.
Decision
Cut and combined steps, keeping only what an order truly needed.
Result
Checkout went from 5 steps to 2, and orders improved.

RAG service

An LLM that sounds confident but is wrong is worse than no answer. This service only answers from retrieved source documents.

  • Chunks documents and stores 768-dim Gemini embeddings in PostgreSQL
  • Top-k cosine search with pgvector, then a grounded prompt
  • Ingestion wrapped in SQL transactions, so no partial writes
